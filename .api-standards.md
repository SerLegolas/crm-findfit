# 📐 API Standards - CRM FindFit

## Struttura delle Route

### Pattern Generale

```
/api/v1/[resource]
├── GET / → Lista (paginata)
├── GET /:id → Dettaglio
├── POST / → Creazione
├── PATCH /:id → Aggiornamento
├── DELETE /:id → Eliminazione
└── [custom] /:id/action → Azioni specifiche
```

### Esempio Completo

```typescript
// 1. Definizione della route
fastify.get('/:id', {
  preHandler: [authenticate],
  schema: {
    params: z.object({ id: z.string().uuid() }),
    response: {
      200: z.any(),
      401: z.object({ error: z.string() }),
      404: z.object({ error: z.string() }),
    },
  },
}, async (request, reply) => {
  // 2. Validazione (già fatta da Zod)
  const { id } = request.params;

  // 3. Logica di business (Controller/Service)
  const result = await Service.getById(id, request.user!.companyId);

  // 4. Response
  if (!result) return reply.code(404).send({ error: 'Non trovato' });
  return reply.send(result);
});
```

## Regole di Validazione

### Zod Schema Examples

#### 1. Query String (Filtri & Paginazione)

```typescript
querystring: z.object({
  page: z.coerce.number().min(1).default(1),
  limit: z.coerce.number().min(1).max(100).default(10),
  search: z.string().optional(),
  status: z.enum(['lead', 'suspect', 'won']).optional(),
})
```

#### 2. Params (ID)

```typescript
params: z.object({
  id: z.string().uuid('ID non valido'),
})
```

#### 3. Body (Creazione/Update)

```typescript
body: z.object({
  name: z.string().min(1, 'Nome obbligatorio'),
  email: z.string().email('Email non valida'),
  phone: z.string().optional(),
}).strict() // Impedisce campi extra
```

## Status Codes

| Code | Descrizione       | Quando usarlo                         |
|------|-------------------|---------------------------------------|
| 200  | Successo          | GET, PATCH                            |
| 201  | Creato            | POST                                  |
| 204  | No Content        | DELETE                                |
| 400  | Bad Request       | Validazione fallita                   |
| 401  | Unauthorized      | Non autenticato                       |
| 403  | Forbidden         | Ruolo insufficiente                   |
| 404  | Not Found         | Risorsa inesistente                   |
| 409  | Conflict          | Duplicato (es. email già usata)       |
| 500  | Internal Error    | Errore server                         |

## Response Format

### Success

```json
{
  "data": { ... }        // Singolo oggetto
}
// o
{
  "data": [ ... ],       // Array
  "total": 42,
  "page": 1,
  "limit": 10
}
// o
{
  "success": true
}
```

### Error

```json
{
  "error": "Messaggio descrittivo",
  "details": [            // Opzionale: dettagli validazione
    {
      "field": "email",
      "message": "Email non valida"
    }
  ]
}
```

## Logging

### Livelli

- **error**: Errori critici (DB down, crash)
- **warn**: Warning (rate limit, tentativi di accesso non autorizzati)
- **info**: Operazioni importanti (login, creazione clienti)
- **debug**: Dettagli di sviluppo

### Esempio

```typescript
fastify.log.info(`Client created by user ${user.id}: ${client.id}`);
fastify.log.error(error, 'Failed to send email');
```

## Performance

### 1. Paginazione (Sempre!)

- **Default**: 10 per pagina
- **Max**: 100 per pagina
- **Sempre** restituire `total`, `page`, `limit`

### 2. Indici Database

```sql
CREATE INDEX idx_clients_company_id ON clients(company_id);
CREATE INDEX idx_clients_user_id ON clients(user_id);
CREATE INDEX idx_tasks_client_id ON tasks(client_id);
```

### 3. Caching (opzionale)

- Template email → Cache (aggiornare solo su modifica)
- Dati azienda → Cache
- Use `@fastify/caching`

## Security Checklist

- [ ] Validazione input con Zod
- [ ] Authentication su tutte le route protette
- [ ] Authorization (admin vs user)
- [ ] Rate limiting (100/min)
- [ ] CORS configurato
- [ ] SQL Injection (usare Drizzle ORM)
- [ ] XSS Protection (sanitize HTML)
- [ ] HTTPS in produzione
- [ ] JWT con expirazione
- [ ] Password hashing (bcrypt)

## Versioning

### Policy

- **v1**: Stabile, supporto minimo 6 mesi
- **v2**: Breaking changes, con deprecation notice

### URL Pattern

```
/api/v1/...  → Versione corrente
/api/v2/...  → Nuova versione
```

## Naming Conventions

### URL

- **Resource**: plural (`/clients`, `/tasks`, `/notes`)
- **Actions**: verb (`/send`, `/sync`, `/export`)
- **Nested**: `/clients/:id/tasks`

### Query Parameters

- **Filtri**: `status`, `categoria`, `userId`
- **Paginazione**: `page`, `limit`
- **Ordinamento**: `sort`, `order`
- **Ricerca**: `search`

### Headers

- **Content-Type**: `application/json`
- **Authorization**: `Bearer <token>`
- **Accept-Language**: `it-IT`, `en-US`

## Error Messages

### Pattern

- **Sempre** in italiano (per gli utenti finali)
- **Chiari e descrittivi** (non tecnici)
- **Non rivelare dettagli di sistema** (stack trace solo in dev)

### Esempi

```
✅ "Email già utilizzata"
✅ "Cliente non trovato"
✅ "Accesso negato: solo admin"
❌ "SQL Error: UNIQUE constraint failed"
❌ "500 - Internal Server Error"
```
